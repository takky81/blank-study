# 設問交換の取込ファイル作成

エクスポート（`question-exchange-*.json`）を読み、修正・追加の操作だけを含む取込ファイルを作る。
補助ツールは同じディレクトリの `qx.py`（`python -I <このディレクトリ>/qx.py <サブコマンド> ...`）。
作業ファイルは scratchpad の作業ディレクトリ（以下 `$W`）に置く。

## 1. 作成条件を質問する

引数にエクスポートのパスがなければ、まずパスを尋ねる。続けて AskUserQuestion で次の1問を聞く（推奨を先頭に置く）。

| header | 質問 | 選択肢 |
|---|---|---|
| 追加設問 | 正答率100%のキーワードに、別の観点の設問を追加するか | 追加する・疑義付きは除外（推奨）／追加する・疑義付きも含む／追加しない |

回答を merge のオプションに対応させる（`--forbid-digit-answer` は常に付ける）。
- 「疑義付きは除外」→ `--create-for-perfect --skip-doubt-create`
- 「含む」→ `--create-for-perfect`
- 「追加しない」→ どちらも付けない（追加設問も作らない）

次の条件は固定で、質問しない。
- 計算問題は許さない。具体的な計算が必要な設問は、計算方法や式を問う形にする。
- 誤答には存在しない用語を使ってよい。
- 目視レビューは行わない。機械チェック（merge）でエラー0件になれば完了とする。

## 2. 作問ルール（常に適用）

- **変更が不要な設問は取込ファイルに含めない**（compact op に書かない）。
- **フラグ付き設問は必ず修正する。** 解説要求（explanation-request）は解説を充実させる。
- **疑義（doubt）は理由とメモに応じて直す。** 別の観点の設問に作り直してもよいが、必須ではなく、問題点を直すだけでもよい。prep が `in/cNN.txt` に `理由=` と `メモ=「…」` を出す。
  - `answer_guessable`（知識なしで当てられる）: 推測できる原因を消す。誤答をもっともらしくする、ヒントになる語を外す。設問文も選択肢も変えないと merge がエラーにする。
  - `low_value`（覚える価値が低い）: 覚える価値のある観点に問い直す。キーワードの特徴や具体的な要素を問う形にしてよい。言い回しの調整だけでは足りない。
  - `defective`（欠陥がある）・`unclear`（あいまい）: 欠陥やあいまいな点を直す。誤答に別の正解がないか、問題文で答えが一つに決まるかを確かめる。
  - メモ: メモの指示に従う。メモの中に、取込ファイルでは指定できない指示がある場合は、報告でユーザーに伝える。例えば「解答履歴を消さなくてよい」は、取込画面の「履歴を引き継ぐ」チェックで対応する。
  - `answer_guessable` 以外の理由かメモがある設問で、設問文も模範解答も変えていないと、merge がエラーにする。
- **解説のない設問には短い解説を付ける。**
- **問題文や選択肢の略語は、解説で正式名称を併記する**（例: `TLS（Transport Layer Security）`）。
- **知識なしで解ける設問にしない。** 具体的には次の3つ。
  - 誤答が常識で除外できる。誤答は、ありがちな勘違いや、別の場面では正しい対策など、もっともらしいものにする。
  - 問題文の語が正答にだけ含まれる（後述の単語一致チェック）。
  - 正答だけがぼかした表現、誤答だけ「必ず」「一切」などの言い切り、正答だけ極端に長い。
- **正答はキーワードでも、キーワードに関連する別の概念・特徴でもよい。**
- 問題文と選択肢が噛み合わないなど、データが壊れている設問は作り直す。
- 法令・制度の設問は、改正で変わりやすい事実（施行年、数値基準）を断定しすぎない。

## 3. 単語一致チェック（修正必須）

`qx.py` の `overlap_error` が、問題文と選択肢の語の一致度を数える。正答の一致度が誤答より明らかに高い設問は **修正必須** で、merge はエラーにする。

- **語の単位**: 英数字の語（2文字以上）、漢字の連続（2文字以上）、カタカナの連続（3文字以上）。ひらがなは数えない。
- **一致の判定**: 問題文の語ごとに判定する。
  - 英数字: 選択肢に同じ語があれば一致
  - 漢字: 2文字の部分列が選択肢に含まれれば一致
  - カタカナ: 3文字の部分列が選択肢に含まれれば一致
- **一致度**: 一致した語1つにつき1点。4文字以上の英数字・カタカナ語は2点。
- **除外**: 設問の決まり文句（適切・記述・特徴など）と、4つの選択肢すべてに現れる部分列は数えない。
- **判定**: 次のどちらかなら修正必須。
  - 正答の一致度 a が2以上で、誤答の最大 d との差が max(1, a/3) 以上
  - 正答の一致度 a が1以上で、誤答の一致度がすべて0（問題文の語が1つでも正答にだけ含まれる）
- **直し方**: ヒントになっている語を問題文から外して言い換える。または、その語を含むもっともらしい誤答を加える。
  - 例: 「キーボードを打つリズムで本人確認」→ キーストローク認証、は問題文の言い換えで直す。
  - 例: 正答「アクセスログ」には、誤答に「アクセス制御リスト」を入れる。

既存の設問がこのチェックに該当する場合、修正しないと merge がエラーにする。prep が `in/cNN.txt` の該当行に `⚠` を付けるので、それを見て修正する。

## 4. 手順

1. **準備**: `python -I qx.py prep <export.json> $W` を実行すると、`$W/order.json` と `$W/in/cNN.txt`（40キーワードずつ）ができる。最初に総数（キーワード数、設問数、フラグ数、解説なしの数、正答率の内訳）を確認してユーザーに伝える。
2. **作問**: `in/cNN.txt` を1つずつ読み、`$W/out/cNN.json` に compact op の配列を書く。
   - 形式: `{"k":キーワード番号, "q":設問番号(新規は省略), "t":設問文, "a":模範解答, "c":[誤答3], "e":解説}`
   - 1チャンク書くたびに merge で検証し、エラーを直してから次へ進む。長くかかるので、数チャンクごとに進捗を一言伝える。
3. **検証と結合**: `python -I qx.py merge <export.json> $W <出力パス> [オプション]` を実行する。
   - 出力の既定は、エクスポートと同じディレクトリの `import-YYYYMMDD.json`。
   - エラーが0件のときだけ書き出す。
   - 主な検査: 誤答の数と重複、正答の問題文への混入、空欄、単語一致、疑義の理由に対する直し不足、フラグ付き・解説なし・単語一致該当の既存設問の修正漏れ、追加設問の漏れ。
4. **報告**（日本語）: 次の内容を伝える。
   - 件数: 操作数、update、create、変更なし
   - フラグ付き・解説なしの設問がすべて修正済みであること
   - 疑義の理由ごとの件数と、取込時に手作業が要るメモ（履歴の引き継ぎなど）
   - 単語一致チェックで直した数
   - 目視レビューは行っていないこと、確認していない点（法令・制度の事実など）

作成後にユーザーから見直しを求められた場合は、次の手順で行う。
- `python -I qx.py review <取込ファイル> $W/review.txt` で1問1行の一覧を作り、全件を読む。
- 直す内容を `$W/fix.json`（`[{"i":行番号, "t"?, "a"?, "c"?, "e"?}]`）にまとめる。
- `python -I qx.py applyfix $W <取込ファイル> $W/fix.json` で反映し、merge をやり直す。
