# 穴埋め学習アプリ 仕様書

本書は、決定表で表せないもの（システム構成・データモデル・データ形式・アルゴリズム）だけを扱う。
機能の振る舞いは決定表を正とする（`spec/tables/*.jsonl` / §7）。

---

## 1. 概要

Markdown で書いたドキュメントの一部を空欄（キーワード）として埋め込み、それを穴埋め形式で解答することで学習するアプリ。

- 教材は Markdown で記述し、アプリ内で編集・プレビューできる
- ドキュメント内に埋め込んだキーワードがそのまま出題対象になる
- 解答結果は蓄積され、間隔反復（SRS）にもとづいて出題順が決まる

### 1.1 用語

| 用語 | 定義 |
| --- | --- |
| 科目 | 教材の最上位の分類 |
| 教材 | 1つのドキュメント。章のツリーを持つ。キーワードIDの一意性の範囲 |
| 章 | 教材内の構造単位。ネスト可能。Markdown 本文の保持単位 |
| キーワード | ドキュメント内の空欄。正答・タグ・誤答選択肢を持つ |
| 正答 | キーワードの答えとして受理される文字列。複数持てる |
| 誤答選択肢 | 選択肢形式で出題する際の、不正解の選択肢 |
| 出題範囲 | 1回の解答で出題対象とする章の集合 |
| 表示範囲 | 解答画面で解答者に見せるドキュメントの範囲 |
| 保存形式 | キーワードをIDだけで参照する本文の形（§4.3） |
| 展開形式 | 正答・タグ・誤答選択肢を本文に書き出した形（§4.3） |

## 2. システム構成

### 2.1 技術スタック

| 領域 | 採用 |
| --- | --- |
| フロントエンド | React + Vite (TypeScript) |
| ホスティング | GitHub Pages |
| バックエンド / DB | Supabase (PostgreSQL) |
| 認証 | Supabase Auth（メールアドレス + パスワード） |
| CSS / UI | Tailwind CSS + shadcn/ui |
| Markdown エディタ | CodeMirror |
| ユニットテスト | Vitest |
| E2Eテスト | Playwright |
| 決定表の生成スクリプト | Node (TypeScript) |

### 2.2 配信

- GitHub Pages は静的配信のみのため、サーバーサイドのコードを持たない
- データアクセスはブラウザから Supabase へ直接行う
- サブパス配信になるため、Vite の `base` とルータの `basename` を合わせる

### 2.3 認証とアクセス制御

- Supabase Auth のメールアドレス + パスワード認証を使う
- サインアップは閉鎖する。アカウントは Supabase 管理画面から手動で作成する
- 確認メール（email confirmation）は無効化する
- メールアドレスは一意なログインIDとしてのみ機能する
- 全テーブルで RLS を有効化し、`owner_id = auth.uid()` を基本ポリシーとする
- 公開されるのはフロントエンドの JS と Supabase の URL / anon key のみ。実際の権限は RLS が決める

## 3. データモデル

### 3.1 subjects（科目）

| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | PK |
| owner_id | uuid | FK → auth.users |
| name | text | 科目名 |
| sort_order | int | 表示順 |
| created_at / updated_at | timestamptz | |

### 3.2 materials（教材）

| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | PK |
| subject_id | uuid | FK → subjects |
| owner_id | uuid | FK → auth.users |
| name | text | 教材名 |
| sort_order | int | 表示順 |
| created_at / updated_at | timestamptz | |

### 3.3 chapters（章）

| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | PK |
| material_id | uuid | FK → materials |
| parent_id | uuid / null | FK → chapters。null なら最上位 |
| title | text | 章タイトル |
| body | text | Markdown 本文。保存形式で持つ（§4.3） |
| sort_order | int | 同じ親の中での表示順 |
| created_at / updated_at | timestamptz | |

章の階層は DB の親子関係で表現し、Markdown の見出しレベルとは独立。

### 3.4 keywords（キーワード）

| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | PK（内部ID） |
| material_id | uuid | FK → materials |
| chapter_id | uuid | FK → chapters。最後に本文中で検出された章 |
| doc_id | text | ドキュメントに埋め込まれるID。小文字英数字6桁 |
| answers | text[] | 正答の配列。先頭を代表表記として扱う |
| tags | text[] | タグ |
| wrong_choices | text[] | 誤答選択肢 |
| is_active | bool | どの本文にも出現しない場合 false |
| created_at / updated_at | timestamptz | |

制約：`unique (material_id, doc_id)`

キーワードの実体のマスタはこのテーブルであり、本文には複製されない。

### 3.5 keyword_stats（学習状態 / SRS）

| 列 | 型 | 説明 |
| --- | --- | --- |
| keyword_id | uuid | PK, FK → keywords |
| owner_id | uuid | FK → auth.users |
| total_count | int | 出題回数 |
| correct_count | int | 正答回数 |
| repetition | int | SM-2 の連続正解回数 |
| ease_factor | numeric | SM-2 の EF |
| interval_days | numeric | 現在の復習間隔（日） |
| due_at | timestamptz | 次の復習予定日時 |
| last_answered_at | timestamptz | 最終解答日時 |

### 3.6 answer_logs（解答履歴の明細）

| 列 | 型 | 説明 |
| --- | --- | --- |
| id | uuid | PK |
| keyword_id | uuid | FK → keywords |
| owner_id | uuid | FK → auth.users |
| format | text | `choice` / `text`。実際に出題した形式 |
| input | text | 解答者の入力 |
| is_correct | bool | 正誤 |
| expanded | bool | 表示範囲を拡張したか |
| answered_at | timestamptz | |

### 3.7 リレーション

```text
auth.users
  └─ subjects
       └─ materials
            ├─ chapters (self-referencing tree)
            └─ keywords ─┬─ keyword_stats
                         └─ answer_logs
```

削除の連鎖は、科目と教材を消したときは配下の解答履歴まで消し、章を消したときはキーワードを非活性にして履歴を残す。

## 4. データ形式

### 4.1 キーワード埋め込み記法

```text
{{正答1,正答2,正答3|id=a3f9k2|tags=タグ1,タグ2|wrong=誤答1,誤答2}}
```

- `|` で区切られたセグメントの並び。1つの記述は1行に収める
- 第1セグメントは正答リスト（カンマ区切り）。ラベルを持たない
- 以降は `key=value` 形式。順不同、すべて省略可能

| キー | 意味 | 省略時 |
| --- | --- | --- |
| （第1セグメント） | 正答リスト | IDのみの形を除き必須 |
| `id` | キーワードID | 保存時・インポート時に自動採番 |
| `tags` | タグのリスト | タグなし |
| `wrong` | 誤答選択肢のリスト | 出題時に自動生成 |

### 4.2 エスケープ

区切り文字（`,` `|`）を含む値はダブルクォートで囲む。クォート自身を含める場合は連続したクォートで1つのクォートを表す（CSV と同じ規則）。

```text
{{"1,000",千|tags=数値}}
{{"A|B方式"|tags=用語}}
```

### 4.3 本文の2つの形

キーワードの実体のマスタは `keywords` テーブル。`chapters.body` はキーワードをIDで参照するだけで、実体を複製しない。

**保存形式** — `chapters.body` に持つ形。すべてのキーワードをIDのみにする。

```markdown
## 光合成

植物は葉緑体で {{id=a3f9k2}} を行う。
夜間は {{id=a3f9k2}} を行わない。
```

**展開形式** — 編集画面とエクスポートで見せる形。章の中で最初に出現する1か所だけフル形式にし、2回目以降はIDのみのままにする。

```markdown
## 光合成

植物は葉緑体で {{光合成,炭酸同化|id=a3f9k2|tags=生物|wrong=呼吸,蒸散}} を行う。
夜間は {{id=a3f9k2}} を行わない。
```

### 4.4 エクスポート zip の構成

- 章の階層をフォルダ構成で表現し、各章を1つの `.md` ファイルとする
- 並び順はフォルダ名・ファイル名の連番プレフィックスで表す。連番は章タイトルに含めない
- 各フォルダの `index.md` がその章自体の本文
- zip のファイル名を教材名とする
- メタ情報ファイル・画像・学習履歴は含めない

```text
テクノロジ系.zip
  010_基礎理論/
    index.md
    010_2進数.md
    020_論理演算.md
  020_アルゴリズム/
    index.md
```

## 5. アルゴリズム

### 5.1 SRS（SM-2 相当）

品質 q は 正解 = 5、不正解 = 0。

```text
正解のとき:
  repetition += 1
  interval = 1                      (repetition == 1)
  interval = 6                      (repetition == 2)
  interval = round(interval * EF)   (repetition >= 3)

不正解のとき:
  repetition = 0
  interval = 1

EF の更新:
  EF = EF + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02))
  EF は 1.3 を下限とする

due_at = now() + interval 日
```

`round` は小数点以下 0.5 を切り上げる。

### 5.2 定数

しきい値はコード内の1か所にまとめ、あとから変更できるようにする。

| 定数 | 値 | 使いどころ |
| --- | --- | --- |
| 定着とみなす出題回数 | 3回以上 | 解答形式の自動判定、学習履歴の区分 |
| 定着とみなす正答率 | 90%以上 | 同上 |
| 選択肢の数 | 4（正答1 + 誤答3） | 選択肢の生成 |
| 連続出題を避ける範囲 | 直近10件 | 出題順 |
| EF の初期値 | 2.5 | SRS |
| EF の下限 | 1.3 | SRS |
| キーワードIDの形式 | 小文字英数字6桁 | ID の採番 |
| 1回の取得件数の上限 | 1000件 | 一覧の件数、出題対象、集計、エクスポート |

1回の取得件数の上限は Supabase 側の設定（ローカルは `supabase/config.toml` の `max_rows`、
本番はプロジェクトの API 設定）で決まる。超えてもエラーにはならず黙って打ち切られるため、
件数はサーバ側で数え、中身が要るところは `src/lib/paged.ts` で分割して取り切る。

## 6. 画面構成

| 画面 | 役割 |
| --- | --- |
| ログイン画面 | メールアドレス + パスワード。サインアップ導線を持たない |
| 科目一覧画面 | 科目の一覧と管理 |
| 教材一覧画面 | 教材の一覧と管理、インポート / エクスポート、解答の開始 |
| 教材編集画面 | 章ツリーと章本文の編集・プレビュー |
| 出題設定画面 | 出題範囲・出題順・解答形式の選択 |
| 解答画面 | 出題 → 解答 → 正誤表示 → 別解登録 |
| 学習履歴画面 | 達成度の階層ビュー、苦手キーワード、日別の学習量 |
| キーワード編集ダイアログ | 正答（複数）・タグ・誤答選択肢の編集 |
| インポート画面 | 取り込む単位・取り込み先・zip の中身の選択 |
| 差分確認画面 | 正答が一致しないキーワードごとに 上書き / 維持 を選ぶ。保存とインポートで共用 |

画面の見た目はワイヤーフレームを正とする。レスポンシブ対応し、ライト / ダークモードを切り替えられる。

## 7. 仕様の管理方法（決定表）

機能の振る舞いは観点ごとの決定表として `spec/tables/*.jsonl` に持つ。

### 7.1 決定表の構成

1つの決定表は5つのブロックからなる。

| ブロック | 内容 |
| --- | --- |
| 条件 | 前提となる状態・入力 |
| 操作 | ユーザーの操作 |
| 結果 | 期待される結果 |
| ユニットテスト | 対応するユニットテスト |
| E2Eテスト | 対応する E2E テスト |

- 行がブロックの要素、列が1つの条件の組み合わせを表す
- 1列 = 1テストケース（1つの `it` ブロック）とする。1つの列が結果を複数持ってよい
- セルには ○ / × / 空欄 のいずれかが入る
- 行タイトルは2列で表示してよい
- 正常系・境界値・異常系をすべて列として持つ。決定表だけを見て、画面デザインを除く全ての機能を再現できることを目標とする

### 7.2 実体（jsonl）

1列を1行として表す。○×ではなく行タイトルをそのまま持つ。

- ファイルは観点ごとに分け、ファイル名の昇順に表示する。1つのファイルに複数の決定表を書いてよい
- `table` が決定表の名前、`col` が列番号。同じ決定表の中で列番号は重複できない
- ブロックは `conditions` / `actions` / `results` / `unit` / `e2e` の5つ
- 各ブロックは、成立する行タイトルを `true`、明示的に不成立の行タイトルを `false` に置く。どちらにも現れない行タイトルが空欄になる
- ブロックの値を配列で書くと、すべて `true` の意味になる
- 行タイトルが2列になるものは `出題順:自動` のようにコロン区切りの1文字列で持ち、HTML 生成時に最初のコロンで分割して2列にする。コロンを含まない行タイトルは2列ぶんを使って表示する
- 行の並びは、その決定表の列を番号順に走査したときの初出順になる
- 任意で `note` を持てる。列に対する補足で、表の下に列番号つきで並ぶ

```jsonl
{"table":"出題順","col":1,"conditions":{"true":["出題順:自動","候補:未出題のものがある"]},"actions":{"true":["次の問題を選ぶ"]},"results":{"true":["出題:未出題を優先する"],"false":["出題:due_at の昇順で出す"]},"unit":["pickNext: 未出題を最優先する"],"e2e":["study.spec: 自動順は未出題から出る"]}
```

### 7.3 表示用HTML

`spec/build-tables.ts` が `spec/tables/*.jsonl` を読んで `spec/dist/index.html` を生成する。

```text
cd spec && npm run build
```

- 各決定表の上に列番号の数値入力欄があり、入力するとその列に関係する行だけが表示され、その列が強調される
- ブロックごとに行全体を色分けする
- 生成物はリポジトリにコミットしない
